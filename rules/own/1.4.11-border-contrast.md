## Applicability

This rule applies to any HTML `input` (except `type` of `hidden`, `button`,
`submit`, `reset`, `image`, `checkbox`, `radio`, `range`, `color`, `file`),
`textarea` and `select` element, and to any element with a `data-slot` of
`input`, `textarea`, `select-trigger` or `native-select`, that is
[visible][], is not [disabled][], and whose computed `border-style` is not
`none` and `border-width` is greater than `0`.

Exception: the element is excluded when it has a visible background whose
contrast against the surrounding color is itself at least 3:1 — the fill,
not the border, then identifies the field.

## Expectation

For each test target, the [contrast ratio][] between the computed
`border-color` and the color behind the border is at least 3:1.

The color behind the border is the first ancestor's background that is not
fully transparent; semi-transparent border colors are composited over it
before measuring. Each theme the design system ships (for shadcn: `:root`
and `.dark`) is a separate test target.

## Background

In shadcn the field border is the token `--input`, read through the class
`border-input`. Changing that one token changes every bordered control, so
one failing pair fails the whole design system — and a token edit is the
place to stop it (see the hook executor).

### Assumptions

- The field's border is the information "required to identify" the
  component in the sense of 1.4.11. A field drawn only by a fill, or by an
  underline, is out of scope of this version of the rule.
- Focus and error states have their own visual identifiers (ring, red
  border) and are covered by separate rules.

### Accessibility Support

None known.

### Related rules

- `color-contrast` (axe) — text only; does not cover this.

## Test Cases

### Passed

#### Passed Example 1

Dark grey border on white: #767676 on #ffffff = 4.54:1.

```html
<label>Email <input type="email" style="border: 1px solid #767676; background: #fff"></label>
```

#### Passed Example 2

shadcn token set where `--input` was raised to meet 3:1:
oklch(0.70 0 0) ≈ #a0a0a0 on white = 2.6:1 is NOT enough;
oklch(0.64 0 0) ≈ #8f8f8f on white = 3.2:1 passes.

```html
<style>:root { --input: oklch(0.64 0 0); --background: #fff }</style>
<input type="text" style="border: 1px solid var(--input); background: var(--background)">
```

### Failed

#### Failed Example 1

shadcn 4.21 default light theme: `--input: oklch(0.922 0 0)` = #e5e5e5 on
white = 1.26:1.

```html
<style>:root { --input: oklch(0.922 0 0); --background: oklch(1 0 0) }</style>
<input type="text" style="border: 1px solid var(--input); background: transparent">
```

#### Failed Example 2

shadcn 4.21 default dark theme: `--input: oklch(1 0 0 / 15%)` composited on
`--background: oklch(0.145 0 0)` = #2f2f2f on #0a0a0a = 1.47:1.

```html
<style>.dark { --input: oklch(1 0 0 / 15%); --background: oklch(0.145 0 0) }</style>
<div class="dark"><input type="text" style="border: 1px solid var(--input)"></div>
```

### Inapplicable

#### Inapplicable Example 1

The field is disabled.

```html
<input type="text" disabled style="border: 1px solid #e5e5e5">
```

#### Inapplicable Example 2

No border is drawn; the field is identified by its fill (#f0f0f0 on white is
not 3:1 either, but that is a different rule — fill contrast).

```html
<input type="text" style="border: none; background: #f0f0f0">
```

#### Inapplicable Example 3

A checkbox: its box is covered by a separate rule.

```html
<input type="checkbox" style="border: 1px solid #e5e5e5">
```
